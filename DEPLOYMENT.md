# Sports Analyzer — production deployment

The app is one FastAPI process that serves the API, the static frontend, and
three in-process scheduler loops. It stores everything in SQLite. Production
therefore needs **one always-on instance with a persistent volume**, not a
static host and not a serverless function.

## What is already prepared

- `Dockerfile` — Python 3.12 image, non-root `app` user, one Uvicorn worker.
- `docker-entrypoint.sh` — seeds the volume from `data/sports_analyzer.db` on
  first boot, fixes volume ownership, then drops privileges.
- `render.yaml` — Render Blueprint with one Starter service and a 1 GB disk.
- `fly.toml` — Fly.io single machine with a 1 GB volume and an HTTP health check.
- `ADMIN_TOKEN` protection on every `/admin/*` route.
- Production startup refuses to run if `APP_ENV=production` and `ADMIN_TOKEN`
  is missing (fail closed).
- CORS is empty by default in production. The UI is same-origin, so no CORS is
  needed. Set `ALLOWED_ORIGINS` only for a deliberate separate frontend host.
- `/docs` and `/openapi.json` are disabled when `APP_ENV=production`.
- SQLite runs in WAL mode with a busy timeout so the scheduler and an API
  request can overlap safely.
- `SPORTS_ANALYZER_DB` points at `/data/sports_analyzer.db`; `/data` is the
  mounted persistent volume.
- Health check: `GET /health` (no secrets or filesystem paths in the response).

## Required production secrets

| Variable | Required | Purpose |
| --- | --- | --- |
| `ADMIN_TOKEN` | yes | Unlocks `/admin/*` and the Admin screen. Use at least 32 random characters. |
| `FOOTBALL_DATA_TOKEN` | yes for football refresh | football-data.org fixture token. Never put it in the frontend. |
| `APP_ENV` | yes | Must be `production`. |
| `SPORTS_ANALYZER_DB` | yes | `/data/sports_analyzer.db`. |
| `SPORTS_ANALYZER_SCHEDULER` | yes | `1` on the single production instance. |
| `ALLOWED_ORIGINS` | no | Leave empty for same-origin. Comma-separated exact origins otherwise. |
| `PORT` | host-dependent | The Docker command reads it; Fly uses 8001, Render injects its own. |

Generate a token locally, for example:

```powershell
-join ((48..57) + (65..90) + (97..122) | Get-Random -Count 48 | ForEach-Object {[char]$_})
```

Do not put any of these values in Git, `frontend/`, or a screenshot.

## Option A — Render Blueprint (paid Starter + disk)

1. In Render, create/connect the GitHub repository
   `amidubaba18-dotcom/Sports-Analyzer`.
2. Choose **New → Blueprint** and apply `render.yaml`.
3. Set `FOOTBALL_DATA_TOKEN` when prompted. `ADMIN_TOKEN` is generated by
   Render; reveal/copy it and keep it private.
4. Wait for the health check `GET /health` to pass.
5. Open the service URL (for example `https://<service>.onrender.com`) and sign
   in to **Admin** with `ADMIN_TOKEN`.

Current Render pricing must be checked in the dashboard. The free web plan is
not sufficient: it sleeps, has no persistent disk, and would lose database
writes. Do not apply this plan without approving the charge.

## Option B — Fly.io (single machine + volume)

```powershell
fly launch --no-deploy --copy-config --name <unique-app-name>
fly volumes create sports_data --region lhr --size 1
fly secrets set ADMIN_TOKEN="<long-random-token>"
fly secrets set FOOTBALL_DATA_TOKEN="<football-data-token>"
fly deploy
```

`fly.toml` keeps `min_machines_running = 1`, `auto_stop_machines = false`, and
`internal_port = 8001`. Do **not** scale above one machine.

## Option C — any Docker host / VPS

```powershell
docker build -t sports-analyzer .
docker volume create sports-analyzer-data
docker run -d --name sports-analyzer -p 8001:8001 `
  -v sports-analyzer-data:/data `
  -e APP_ENV=production `
  -e ADMIN_TOKEN="<long-random-token>" `
  -e FOOTBALL_DATA_TOKEN="<football-data-token>" `
  -e SPORTS_ANALYZER_DB=/data/sports_analyzer.db `
  -e SPORTS_ANALYZER_SCHEDULER=1 `
  sports-analyzer
```

Put HTTPS in front of it (Caddy, nginx, or the host's proxy). The container
already trusts forwarded headers; do not expose port 8001 directly to the
public internet without TLS.

## Volume and first boot

On first boot the entrypoint copies the committed SQLite snapshot to the
volume. On later boots it leaves the volume alone. This means:

- admin changes, predictions, and imports survive restarts and deploys;
- deleting the volume resets to the snapshot (by design);
- backup before destructive maintenance.

A manual backup (inside the container or on the host) is a consistent copy of
the database plus the export directory:

```sh
sqlite3 /data/sports_analyzer.db ".backup '/data/sports_analyzer.backup.db'"
python /app/scripts/export_data.py --db /data/sports_analyzer.db
```

The export command writes to `/app/data/export` in the image; use `--out` on a
writable path if you want to keep the CSVs on the volume.

## Scheduler expectations

The web process starts these daemon loops unless
`SPORTS_ANALYZER_SCHEDULER=0`:

- Football fixtures: refresh at most every 12 hours; weekly calendar sync;
  grading and board fill every 30 minutes.
- NBA games: refresh when `last_schedule_fetch` is more than 6 hours old;
  publish, quarter/history ingest and board invalidation follow the refresh.
- NBA people: availability every 3 hours, rosters daily, player stats at most
  every 3 days.

All loops use non-blocking locks or idempotent upserts so an overlapping manual
button press does not create duplicate predictions or duplicate game rows.
Running more than one Uvicorn worker would defeat that guarantee.

## Honest limitations

- There is no free always-on host with a persistent disk in this setup. A free
  static host cannot run the API or the schedulers.
- No custom domain is configured. The provider URL is the public URL.
- The repository is public; the database and screenshots are public data, but
  `.env` is ignored and must never be committed.
- Live HIT/MISS remains empty until live picks have results. Only the synthetic
  demo database (`?demo=1`, served locally on port 8002) shows settled rows.
- The NBA provider has a 2025-26 history gap and no played 2026-27 games yet.
- Period markets depend on quarter data; availability does not include
  confirmed starting lineups.
